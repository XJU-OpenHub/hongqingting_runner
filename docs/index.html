批量上传跑步数据

已知问题： 目前只有 location_1_6km · 1.6 km 这条轨迹是调通的，其他三条 （1km / 1.16km / 12km）还有 bug， 暂时不要选。
批量上传两个变量怎么理解：
  • 往前推多少天 = 要补多少天的跑步数据。填 30 就是从 30 天前一路补到今天，每天跑一次，共发 30 个包。
  • 每天偏移 (i - 此值) = 每次运动的开始时间相对"i 天前的此刻"挪多少。 Python 的 begintime 公式是 现在 - (i - 此值) × 86400，1 天 = 86400 秒， 所以 0.1 就是 2.4 小时。
    假设现在是下午 5 点：
    • 填 0：每次都严格在"i 天前的下午 5 点"开始
    • 填 0.3：每次都比"i 天前的下午 5 点"晚 7.2 小时（约凌晨 0:12 开始，i=0 那次会落到明天凌晨）
    • 填 -0.3：每次都比"i 天前的下午 5 点"早 7.2 小时（约上午 9:48 开始）
    Python 原代码用的是 0.3，目的是让上传时间不要全卡在同一时刻、不要太规律。
